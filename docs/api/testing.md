# API tests

Go `testing`, `httptest`, the race detector and real PostgreSQL.

## Running

```sh
make db                   # PostgreSQL and the tests' database, lewcontext_test
make test                 # unit and integration tests (and Vitest), with .env.testing
make check                # gofmt + go vet (and the web checks)
cd apps/api && go run golang.org/x/vuln/cmd/govulncheck@latest ./...   # dependency audit
```

Integration tests never skip: without the database they fail with "start it with make db". One package or test runs directly too (`cd apps/api && go test ./internal/mail -run TestX`), with the same database, since `dbtest` reads `.env.testing` itself.

## Integration tests

- `dbtest.Open(t)` connects to the `DATABASE_URL` in `.env.testing` (`lewcontext_test`), found by walking up from the working directory and **never read from the process environment**, so a development `DATABASE_URL` can't be used by mistake. It refuses a host that isn't local (`127.0.0.1`, `::1`, `localhost`, `postgres`) or a database not named `*_test` / `*_test_<port>`. It creates a unique `lewcontext_test_<timestamp>` schema, pins `search_path` to it, and drops only that schema at cleanup. Existing data is never touched.
- `integrationServer(t)` (in `httpapi`) migrates the schema (and checks a second migrate is a no-op), then returns a `*Server` and the DB.
- `call(t, handler, method, path, body, csrf, cookie, wantStatus)` sends a request with the trusted Origin and JSON content type, from `127.0.0.1`, and fails on an unexpected status. To test the client IP behind a proxy, set `s.Config.ClientIPHeader` and `TrustedProxies` before `s.Routes()` (`behindProxy` in `client_ip_integration_test.go`).
- `signedIn(t, db, faker)` returns a fake user's `factory.Session`. Use `session.UserID`, `session.Cookie()` and `session.CSRFToken`.
- `must(call)(t)` returns a two-result call's value or fails the test: `user := must(factory.Users.CreateOne(ctx, db, f))(t)`. Go only lets a two-result call fill a whole argument list, hence the trailing `(t)`.
- `idOf(t, db, "users" | "workspaces" | "projects", publicID)` and `emailOf(t, db, userID)` look records up instead of one-off SQL. Events have `eventsNamed` and `onlyEvent` (`events_integration_test.go`).
- `ownedWorkspace(t, db, faker, userID)` creates a workspace the user owns; `workspacePath(workspace.PublicID, "/projects")` builds its API paths.

## Test data comes from factories

```go
f := factory.TestFaker(t)
session := signedIn(t, db, f)
workspace := ownedWorkspace(t, db, f, session.UserID)
factory.ProjectsIn(workspace.ID).Create(ctx, db, f, 45)
```

- Set only the fields a test asserts on (with `State` or `Sequence`) and leave the rest random. See [seeding.md](seeding.md).
- Don't write rows by hand, and don't set up data through API calls. The exception is when that endpoint is what's being tested: registration, login, rotation, logout, the session cap and the limiters go through the real endpoints.
- To test rate limits, pre-fill counters (`factory.RateLimits` with `ForAccount`/`ForIP`, or `ForLimit(name, subject)` for any limit, where the subject is an IPv4 address or IPv6 /64 (`2001:db8:1:2::/64`), an email or a user's `usr_` ID, and `Exhausted`) in a test whose requests haven't created the counter yet; `retryWithin` checks `Retry-After`. The read budget is in memory: fill it with `s.memoryLimits.allow`.
- Reset links: `factory.PasswordResets` with `ResetFor(userID)` (and `ExpiredReset`) keeps the raw `Token`. To test a listener end to end, `mailServer(t)` registers both (reset links and invitations) with a `mailbox` driver and returns `deliver()`, which runs the worker once; `tokenIn` and `invitationTokenIn` read the link from a sent message. Invitations: `factory.InvitationsTo(workspaceID)` with `Sent` (keeps the raw `Token`), `ExpiredInvitation` and `InvitedAs`.
- A failing test prints `fake data seed N`; rerun it with `FAKER_SEED=N`.

## What to cover

- **Validation:** table-driven unit tests for parsing (e.g. `TestPageRequest`, `TestProjectFilter`).
- **Security boundaries:** 401 without a session, 403 without CSRF or with a bad Origin or a role without the permission, a non-member's 404 on every workspace route, another workspace's data returning 404 or empty results, and no numeric `id` in responses.
- **Persistence:** results come back from the database, ordering is stable across pages, and filters combine.
- Don't add tests that only mirror trivial code.
