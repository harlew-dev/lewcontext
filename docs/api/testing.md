# API tests

Go `testing`, `httptest`, the race detector and real PostgreSQL.

## Running

```sh
make db                   # PostgreSQL and the tests' database, lewcontext_test
make test                 # unit and integration tests (and Vitest), with .env.testing
make check                # gofmt + go vet (and the web checks)
cd apps/api && go run golang.org/x/vuln/cmd/govulncheck@latest ./...   # dependency audit
```

Integration tests never skip: without the database they fail with "start it with make db". One package or test runs directly too (`cd apps/api && go test ./internal/mail -run TestX`), with the same database, since `dbtest` reads `.env.testing` itself.

## Integration tests

- `dbtest.Open(t)` connects to the `DATABASE_URL` in `.env.testing` (`lewcontext_test`), found by walking up from the working directory and **never read from the process environment**, so a development `DATABASE_URL` can't be used by mistake. It refuses a host that isn't local (`127.0.0.1`, `::1`, `localhost`, `postgres`) or a database not named `*_test` / `*_test_<port>`. It creates a unique `lewcontext_test_<timestamp>` schema, pins `search_path` to it, and drops only that schema at cleanup. Existing data is never touched.
- **Integration tests sit beside the controllers they cover**, in the external test package: `endpoints/workspace/projects_integration_test.go` is `package workspace_test`, so it can import `router` and build the real server. Tests of more than one area (`TestAuthenticationAndProjectIsolation`, events, limits, client IPs, the page gate) are `httpapi_test` in the core's folder. They keep the `_integration` suffix, as they sit beside unit tests.
- Each test package has a short `server(t)` that returns a `*httpapi.Server` on `apitest.Database(t)` (a migrated schema of its own, checking a second migrate is a no-op) and the DB; `router.New(s)` is its handler. Tests that need another config build their own with `httpapi.New(&store.Store{DB: db}, …)`.
- **Shared helpers are in `httpapi/apitest`**, which only tests import (`TestHTTPLayout` checks) and which imports neither `httpapi` nor `router`, so tests inside either can use it. Helpers used by one package's tests stay in it (`inbox`, `adminSignedIn`, `behindProxy`, `memberFixture`).
- `apitest.Call(t, handler, method, path, body, csrf, cookie, wantStatus)` sends a request with the trusted Origin and JSON content type, from `127.0.0.1`, and fails on an unexpected status; `apitest.Send` doesn't fail, so goroutines can use it. To test the client IP behind a proxy, set `s.Config.ClientIPHeader` and `TrustedProxies` before `router.New(s)` (`behindProxy` in `client_ip_integration_test.go`).
- `apitest.SignedIn(t, db, faker)` returns a fake user's `factory.Session`. Use `session.UserID`, `session.Cookie()` and `session.CSRFToken`.
- `apitest.Must(call)(t)` returns a two-result call's value or fails the test: `user := apitest.Must(factory.Users.CreateOne(ctx, db, f))(t)`. Go only lets a two-result call fill a whole argument list, hence the trailing `(t)`.
- `apitest.IDOf(t, db, "users" | "workspaces" | "projects", publicID)`, `EmailOf(t, db, userID)` and `PublicIDOf(t, db, userID)` look records up instead of one-off SQL. Events have `EventsNamed`, `OnlyEvent`, `Is` and `CheckPayloadIDs`; `Reached` is the one `rate_limit.reached`.
- `apitest.OwnedWorkspace(t, db, faker, userID)` creates a workspace the user owns; `apitest.WorkspacePath(workspace.PublicID, "/projects")` builds its API paths. `WithMFA` makes an account with MFA on (`CodeAt` for its codes), and the bodies (`LoginBody`, `CodeBody`, `TokenBody`, `ChangeBody`) and `ErrorField`, `CookieNamed` save repeating JSON.
- **Tests that need internals stay with them:** the router's tests hold `TestWorkspacePermissionMatrix`, `TestWorkspaceMutationsNeedAPermission`, `TestAdminRoutesStayInTheAdminGroup`, `TestAdminMutationsNeedARole` and `TestOnlyFiveRoutesAllowUnverified`, which read its registry (`TestAdminRoutesStayInTheAdminGroup` also fails on a registration it can't read, or `handle`; `TestAdminMutationsNeedARole` on `OwnSessions` outside its two routes); the core's `admin_access_test.go` holds the refused-address set's cap, the refusal queue dropping when full, and the networks a moved session is compared by; the core's hold the two in-memory budget tests (`budgets_integration_test.go`), which fill the counter and send requests through the middleware directly; an area's own unit tests (`endpoints/workspace/validation_test.go`) use its unexported validation.

## Test data comes from factories

```go
f := factory.TestFaker(t)
session := apitest.SignedIn(t, db, f)
workspace := apitest.OwnedWorkspace(t, db, f, session.UserID)
factory.ProjectsIn(workspace.ID).Create(ctx, db, f, 45)
```

- Set only the fields a test asserts on (with `State` or `Sequence`) and leave the rest random. See [seeding.md](seeding.md).
- Don't write rows by hand, and don't set up data through API calls. The exception is when that endpoint is what's being tested: registration, login, rotation, logout, the session cap and the limiters go through the real endpoints.
- To test rate limits, pre-fill counters (`factory.RateLimits` with `ForAccount`/`ForIP`, or `ForLimit(name, subject)` for any limit, where the subject is an IPv4 address or IPv6 /64 (`2001:db8:1:2::/64`), an email or a user's `usr_` ID, and `Exhausted`) in a test whose requests haven't created the counter yet; `apitest.RetryWithin` checks `Retry-After`. The read budgets are in memory: only the core's tests can fill them (`s.memoryLimits.Allow`).
- Reset links: `factory.PasswordResets` with `ResetFor(userID)` (and `ExpiredReset`) keeps the raw `Token`; block links, `factory.EmailBlockLinks` with `BlockLinkFor(email)` (and `ExpiredBlockLink`), and blocked addresses `factory.EmailBlocks` with `Blocked(email)`. An admin session inside its step-up window: `factory.AdminSessions` with `SteppedUp` (`operatorSignedIn` in the admin tests makes an operator's). To test a listener end to end, `apitest.Mail(t, s.Repo, s.Config.Origin)` registers both (reset links and invitations) with an `apitest.Mailbox` driver and returns `deliver()`; `mailServer(t)` in each package wraps it with `server(t)`, which runs the worker once; `tokenIn` and `invitationTokenIn` read the link from a sent message. Invitations: `factory.InvitationsTo(workspaceID)` with `Sent` (keeps the raw `Token`), `ExpiredInvitation` and `InvitedAs`.
- A failing test prints `fake data seed N`; rerun it with `FAKER_SEED=N`.

## What to cover

- **Validation:** table-driven unit tests for parsing (e.g. `TestPageRequest`, `TestProjectFilter`).
- **Security boundaries:** 401 without a session, 403 without CSRF or with a bad Origin or a role without the permission, a non-member's 404 on every workspace route, another workspace's data returning 404 or empty results, and no numeric `id` in responses.
- **Persistence:** results come back from the database, ordering is stable across pages, and filters combine.
- Don't add tests that only mirror trivial code.
- **Naming checks** ([../checks.md](../checks.md)) are a pure function (names in, the ones breaking the rule out, each with its message), a table test of names it must accept and refuse, and a run on the real code (reflection or `go/parser`). Their exceptions are lists in the test, each with its reason.
